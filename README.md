# The Fitness Falcon

Static website with grouped blog and landing pages.

## Layout

- `index.html`: homepage.
- `blogs/index.html`: all-articles archive.
- `blogs/<article-slug>/index.html`: 167 blog articles.
- `pages/<page-slug>/index.html`: About Us, Editorial Policy, Contact Us, Privacy Policy, Publisher, and Write For Us.
- `category/<category-slug>/index.html`: 19 category archives.
- `assets/`: shared images, design system styles (`custom-style.css`, `footer.css`), shared scripts (`falcon-core.js`, `falcon-search-data.js`, `search-results.js`), fonts, and the search index.
- `components/`: shared global header (`header.html`), footer (`footer.html`), layout shell (`layout.html`), and reusable component patterns (breadcrumbs, cards, CTA banners).
- `scripts/`: build, validation, architecture migration, and local preview commands.
- `audit/`: link validation, migration history, backup locations, and route mappings.
- `old-website/`: WordPress exports, archived flat pages/redirects, and retired import tools.

Canonical pages share:
- 1 shared global header (`components/header.html`)
- 1 shared global footer (`components/footer.html`)
- 1 global layout system (`<main id="main-content" class="falcon-main-layout">`)
- Shared design system & tokens (`assets/css/custom-style.css`)
- Shared search index and core interactions (`assets/js/falcon-search-data.js`, `assets/js/falcon-core.js`)

Individual pages provide their own content and `<head>` SEO metadata. Author information is defined in `scripts/editorial.py`; do not add credentials that have not been verified.

The sitemap lists every indexable canonical URL. Tag archives remain crawlable with `noindex,follow` and are excluded from the sitemap. Compatibility WordPress sitemaps are generated alongside the main sitemap. The homepage Latest list is regenerated from publication dates by `scripts/build_home.py`. The homepage also carries a "New this month" list of every article from the last 45 days that no other section links, so new URLs are one click from the most-crawled page. Redirects, search data, and sitemaps are regenerated by the build; edit their generators rather than generated files.

Modified dates (`modified_time`, `modified_iso`, `modified_date` in post JSON) must track real content changes, because sitemap `lastmod` and `dateModified` are only useful to search engines when they do. `python3 scripts/restore_modified_dates.py` derives them from git history (first commit with the current visible text), the WordPress export for untouched imports, or the publication time; markup-only edits do not count. Run it after editing article text in bulk, before the build. `tests/test_indexing.py` fails if one day is stamped on most posts.

After each deployment run `python3 scripts/indexnow.py` (all sitemap URLs) or `python3 scripts/indexnow.py /blogs/<slug>/ …` to notify Bing, Yandex and other IndexNow engines; the key file `<key>.txt` in the site root must be live. Google ignores IndexNow: request indexing for priority URLs in Search Console. Search Console access for agents is through the `gsc` MCP server (Composio).

Content review: `audit/content-triage-2026-10-18.md` lists each article with 16-month Search Console demand and a keep / refresh / merge / retire proposal. Articles removed by that review are listed in `content/retired.json` (merged slug to target, or retired); `scripts/build_redirects.py` turns them into 301 and 410 rules, and the source JSON stays in `old-website/retired-posts/` for reference. To retire or merge another article, move its JSON there, add it to the manifest, fix links from other articles, and rebuild.

## Build, check, and preview

```sh
python3 scripts/build.py
python3 scripts/check_site.py
python3 scripts/serve.py --port 8000
```

The preview server handles compatibility redirects; a plain `python3 -m http.server` does not read hosting redirect files.

## URL compatibility

New article URLs use `/blogs/<article-slug>/`; landing pages use `/pages/<page-slug>/`. All site links and search results point directly to these routes.

Old `/article-slug/`, `/article-slug/index.html`, and `/article-slug.html` URLs redirect to their grouped route. The old `/blog/` archive redirects to `/blogs/`. Landing-page URLs have equivalent redirects.

Publish `.htaccess` for Apache hosting with mod_rewrite enabled, or `_redirects` for hosting that supports that format (such as Netlify). Other hosts need the mappings in `audit/routes.json` configured in their redirect system. Do not deploy only the HTML files and omit redirect configuration if old URL compatibility is required.

Migration scripts (`organize.py` and `group_pages.py`) are already applied and should not be rerun. Archived import tools can recreate obsolete pages; retain them for reference only.

Validation covers local page/resource references, CSS dependencies, redirect destinations, and search entries. It does not establish external-site availability or browser-rendered behavior. Original content and backup ZIP paths are retained in the audit reports.

Topic clusters use `cluster_id` and `cluster_role` in post JSON. The post builder generates reciprocal cluster navigation and prioritizes cluster articles in related cards. The walking-pad desk cluster contains one hub and six supporting articles.
